    第 4 週

    LLM 只是在猜下一個字？

    文字生成 AI 就是一直預測下一個字，選字方式決定它有多隨機，prompt 要給正確資訊和清楚指引。

    next-token prediction幻覺temperaturetop-pembeddingtransformerPrompt EngineeringGroq

    資料來源：課堂投影片《04 LLM 只是在猜下一個字？》，文中（p.12）代表投影片頁碼。

    課堂重點

    文字生成 AI 只是預測下一個字的呆萌型 AI 機器人，訓練目標是把它變成「很會接話」的唬爛王。

    設計：用前面的字預測下一個字

    直覺上，對話機器人應該用「客戶說的話 → 客服的回覆」來訓練，但實際上不是。語言模型的設計是看前面的字，預測下一個字。這樣世界上所有句子都能拿來當訓練資料。p.6–9

    但「今天天氣很好」裡，「天」後面可以接「天」也可以接「氣」，這不是函數。所以要用有記憶的神經網路，把前面所有字的資訊融合成一個向量，再預測下一個字，一路接下去。p.10–15

    模型其實是幫字庫裡每個字打分數，再用 softmax 轉成機率。它不知道自己在說什麼，只是覺得下一個字放什麼最順。p.16–20

    RNN 與 Transformer

    有記憶的神經網路有兩種：RNN 一個字一個字算，每次帶著上一步的記憶；Transformer 是 Google 想出的辦法，一次算出所有位置的記憶，可以平行計算。p.23–27

    Transformer 讓每個字產生 Q、K、V 三個向量，用 Q 和每個 K 做內積得到注意力強度，經 softmax 後拿來加權 V。整個過程基本上就是矩陣乘法：p.28–31

    \[\mathrm{Attention}(Q,K,V)=\mathrm{softmax}\left(\frac{QK^T}{\sqrt{d_k}}\right)V\]

    幻覺是特點，不是錯誤

    Karpathy 在 2015 年的文章裡，讓 RNN 生成代數幾何、莎士比亞，課堂上也看到「紅樓夢生成器」，他把這些生成結果叫做 hallucinated（幻覺的）版本。p.33–38

    他的看法是：LLM 是「作夢的機器」，幻覺就是它做的全部事情。幻覺可能對、可能錯，甚至無所謂對錯。我們真正不希望的，是 LLM 助理在需要事實的時候產生幻覺。p.39–40

    規模也很重要：GPT-2 有 15 億參數，GPT-3 有 1,750 億。人一輩子大約讀 10 億字，Llama 3 用了約 15T 的訓練資料，是人類一輩子的 1.5 萬倍，所以它什麼話都接得下去。p.42–45

    選字策略：temperature、top-k、top-p

    最基本的是依機率抽樣。softmax 有「贏者通吃」的效果，所以加上溫度 \(\tau\) 調整：p.52–57

    • \(\tau > 1\)：拉近各字的機率，輸出更隨機。
    • \(\tau < 1\)：拉開差距，輸出更固定。

    實務上 LLM 的分數通常都接近 0，影響沒那麼大，常見設定是 \(\tau = 1\)。p.58

    機率低的字還是可能被抽到，導致胡言亂語。top-k 只從前 k 名選，但有時下一個字只有一種可能；top-p（nucleus sampling，ICLR 2020）從最高機率開始累加，加到超過 p 就停，只在這些字裡重新分配機率再抽。p.59–63

    Embedding：給字一個有意義的向量

    one-hot encoding 只是編號，沒有「意思」。我們希望每個字有一個有意義的特徵代表向量，叫 word embedding。p.66–69

    做法是設計一個代理任務（pretext task），讓電腦必須「懂」輸入才能完成，再取中間隱藏層的輸出當 embedding。Word2Vec 用兩種任務：CBOW 用周圍的字預測中間的字，Skip-Gram 反過來。訓練完，相似的字會靠在一起，還能做出「國王 − 男人 + 女人 ≈ 皇后」這類運算。p.75–80

    Transformer 有自己的 embedding 層，訓練時會一起學。p.83

    使用大型語言模型

    投影片列了五大商業模型（OpenAI、Google、Anthropic、xAI、Meta），以及開源模型。挑模型可以參考 Artificial Analysis 和 Arena 兩個評測網站，但最好自己設計幾個你很懂的測試 prompt，才能判斷回答好不好。p.85–89

    開源模型可以用 LM Studio 或 Ollama 在自己電腦跑。以 4-bit 量化的 200 億參數模型為例，至少要 10GB 以上的記憶體，建議 16GB。不想自己跑，可以用 Groq 的免費 API 或 Ollama Cloud。p.90–98

    Prompt 必殺技

    寫好 prompt 只有兩個重點：正確的資訊和清楚的指引。必殺技是「和 AI 一起寫 prompt」：p.100、p.105–109

    1. 先把只有你知道的內容告訴 AI。
    2. 請 AI 訪問你，問清楚還有哪些地方要釐清。
    3. 請 AI 幫忙補充、查證，最後整理成一份 prompt。

    AI 生成的東西，不管是 prompt 還是成品，一定要自己讀過、改過。這個技巧在 Vibe Coding 也適用：先和 AI 討論，再請 AI 整理出規格。p.110–111

    重要名詞

    • next-token prediction：用前面的字預測下一個字，是語言模型的訓練方式。
    • 幻覺：LLM 生成的內容本質上都是「作夢」，可能對也可能錯。
    • temperature：調整機率分布的參數，越高越隨機。
    • top-p：只從累積機率達到 p 的那幾個字裡抽樣，也叫 nucleus sampling。
    • embedding：把字或資料轉成有意義的特徵代表向量。
    • 代理任務：不是最終目標、而是為了訓練出好的 embedding 而設計的小任務。
    • self-attention：每個字用自己的 Q 去和所有字的 K 比對，決定要參考多少其他字的資訊。

    本週作業

    和 AI 討論，共同設計一份可以直接交給不同 LLM 使用的完整 prompt。要交出最後的 prompt，說明哪些是自己告訴 AI 的、怎麼和 AI 討論；最後的 prompt 必須自己完全讀過並修改；至少在三個 LLM 試用並記錄心得。p.113–114
