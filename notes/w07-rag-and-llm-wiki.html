    第 7 週

    讓 AI 看懂你的世界

    RAG 先找出相關資料再交給 LLM 回答；LLM Wiki 則讓 AI 自己整理知識庫。

    RAGembeddingmetadataKV-CacheLLM WikiContext Engineering

    資料來源：課堂投影片《07 讓 AI 看懂你的世界》，文中（p.12）代表投影片頁碼。

    課堂重點

    RAG 其實就是 Context Engineering：提供正確的資訊，只是改成讓電腦自己去找。

    RAG 的核心：embedding 模型

    寫 prompt 要給「正確的資訊」，RAG（Retrieval-Augmented Generation）就是讓電腦自己去找這些資訊。老師再次強調：要理解原理，不要被大字彙迷惑。p.3–5

    關鍵是一個 embedding 模型，它本質上也是語言模型，把一段文字轉成某個維度的向量，代表這段文字抽象的意思。p.6

    這類模型常用對比學習訓練：問題和正確段落的向量要越近越好，和不相關段落的向量要越遠越好。有些模型會在問題前加 query:、在內容前加 passage:，但這種前綴沒有通用寫法。p.7–9

    資料要怎麼切

    最傳統的做法是把所有檔案丟進一個資料夾，自動切成固定長度的文字塊，例如每塊 500 字、重疊 50 字。但要切多大、法規要不要一條一條切、要重疊多少，都需要考慮。p.10–12

    比較新的做法是自己切成想要的樣子。每份文件分兩部分：真正拿去做 embedding 的文字，以及 metadata，例如標題、來源網址、日期、分類。metadata 可以拿來做關鍵字搜尋或篩選，例如「不要管某位老師怎麼說」。p.13–16

    RAG 的流程

    1. 每份資料都用 embedding 模型算出代表向量，存成向量資料庫。p.17–18
    2. 使用者提問時，問題也轉成向量。p.19
    3. 比對哪些資料和問題最接近，通常不只取一筆，可能還要重新排序（reranking），或把前後文、整篇文章一起拿進來。p.20–22
    4. 把找到的資料和原始問題一起放進新的 prompt，例如「請根據 {retrieved_chunks} 裡的資訊，回應使用者的問題：{question}」。p.23–24

    真的需要 RAG 嗎

    模型的上下文越來越長，全部塞進 prompt 不就好了？這就是 CAG 的想法：用 KV-Cache 技術先把資料的鍵值存起來，直接交給 LLM。p.26–28

    LLM 的「記憶」

    一個系統可以同時用好幾個向量資料庫。外面常說 LLM 有短期記憶和長期記憶：短期記憶就是這次的對話過程，下次就忘了，對話太長也會忘記前面；長期記憶的一種做法，是把過去的對話做成向量資料庫，也就是 RAG。p.30–34

    LLM Wiki：讓 AI 整理你的知識庫

    2026 年 4 月 Karpathy 分享了用 LLM 建立個人知識庫的方法，概念是打造自己的 Wikipedia：p.36–46

    • 資料匯入：把文章、論文等來源放進 raw/，讓 LLM 逐步「編譯」成一系列 .md 檔，包含摘要、反向連結和概念文章。
    • 檢視：用 Obsidian 當前端瀏覽，wiki 幾乎全部由 LLM 撰寫和維護。
    • 問答：wiki 夠大（約 100 篇、40 萬字）時，可以問複雜問題。他原本以為需要複雜的 RAG，但 LLM 自己維護的索引和摘要就夠用了。
    • 輸出與檢查：答案輸出成 Markdown、投影片或圖表，再歸檔回 wiki；也會請 LLM 做健檢，找出不一致或缺漏的資料。

    重要名詞

    • RAG：檢索增強生成，先找相關資料，再讓 LLM 根據資料回答。
    • embedding 模型：把文字轉成代表向量的模型，意思相近的文字向量也相近。
    • 對比學習：讓相關的配對靠近、不相關的配對遠離的訓練方法。
    • metadata：文字塊的附加資訊，例如來源、頁數、標題、日期。
    • reranking：把檢索出來的多筆資料重新排序，挑出最相關的。
    • KV-Cache：把注意力機制算過的 key 和 value 存起來重複使用。
    • LLM Wiki：由 LLM 撰寫和維護的個人 Markdown 知識庫。

    本週作業

    打造自己的 RAG 系統p.50–51：

    1. 找一份有興趣的文件，例如某個規定或相機說明書，用 Vibe Coding 打包成一個個檔案，例如 rag-data.zip。
    2. RAG 1：用自己的資料建立向量資料庫，打包成 vector_embedding.zip。
    3. RAG 2：讀入並解壓縮向量資料庫，做出 RAG 強化的對話機器人。

    W06 打造自己的對話機器人 的機器人只知道對話內容，本週讓它查得到外部資料。KV-Cache 用到 W05 AI 怎麼記得前面說過什麼？ 的 K 和 V。W08 教 AI 做事的方法 會說明 RAG 其實也是一種 AI Agent。本週的 LLM Wiki 在 W09 換你當老闆 會放進「專案資料夾＋規則檔」的脈絡裡再看一次。
